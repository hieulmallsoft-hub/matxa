# Bàn giao mobile – 04/11/2026

Tổng hợp các API mobile cần gọi sau đợt cập nhật luồng đặt KTV, màn KTV, chat và khiếu nại.
Chi tiết JSON đầy đủ xem ở các file được dẫn link; Swagger: `http://149.28.156.66:5600/api/docs`.

Mọi request: `Authorization: Bearer <accessToken>`, base `/api`.

**Nguyên tắc chung**

- Hiện nhãn/nút theo các cờ backend trả (`displayStatus`, `can...`), **không tự suy** từ trạng thái khác.
- Nhận thông báo liên quan đơn → gọi lại API chi tiết đơn để cập nhật màn hình.

## A. App khách

### A1. Đặt KTV và màn chờ — [open-booking-waiting.md](open-booking-waiting.md)

| Màn / thao tác | API | Ghi chú |
|---|---|---|
| Lấy cấu hình (giờ đặt trước tối thiểu, hotline) | `GET /settings/public` | Không cần token. Khoá giờ sớm hơn `now + minAdvanceHours` |
| Danh sách KTV phù hợp | `POST /bookings/matching-technicians` | KTV đang bận đã bị loại sẵn |
| Tạo đơn (chọn 1 KTV) | `POST /bookings` | Body có `technicianId`. Lỗi `400` "Vui long dat lich truoc it nhat X gio" |
| Màn chờ | `GET /bookings/{id}` | Tải lại ~10 giây/lần khi `status: "OPEN"` |
| Bấm **Chọn** KTV thay thế | `POST /bookings/{id}/select-technician` | Body `{ "applicationId": "…" }`. **Chỉ gọi khi người dùng bấm** |
| Hủy đơn | `PATCH /bookings/{id}/cancel` | Body `{ "reasonCode": "WAIT_TOO_LONG" }` |

Trong `GET /bookings/{id}` (màn chờ):

| Trường | Dùng để |
|---|---|
| `requestedTechnicianId` | KTV khách chọn → dòng "Đang chờ **Duc Nguyen** xác nhận" |
| `applications[]` | Danh sách "N KTV đang muốn phục vụ bạn". **Chỉ hiện phần tử `isApplicant: true`** |
| `applications[].distanceKm` / `isAvailable` / `badge` | "2 km" (ẩn nếu `null`) / "Sẵn sàng" / tag `QUALITY` = Chất lượng, `NEW` = Mới |
| `status` | `CONFIRMED` → chuyển sang màn **Đã kết nối** |

Thông báo khách cần xử lý: `REQUESTED_TECHNICIAN_ACCEPTED` (KTV đã nhận → màn Đã kết nối),
`REQUESTED_TECHNICIAN_DECLINED` (KTV từ chối hoặc đã nhận đơn khác), `TECHNICIAN_APPLIED`, `BOOKING_EXPIRED`.

### A2. Chat với KTV theo đơn — [booking-chat.md](booking-chat.md)

| Thao tác | API |
|---|---|
| Mở chat của đơn | `POST /conversations/booking/{bookingId}` |
| Danh sách chat | `GET /conversations` |
| Tin nhắn | `GET /conversations/{id}/messages`, `POST /conversations/{id}/messages` |

**Mới:** mỗi phần tử `GET /conversations` có `canSendMessage`. `false` (đơn đã hủy/hết hạn) → **ẩn ô nhập tin**,
hiện "Đơn đã kết thúc". Gửi vào chat đó sẽ bị `403`.

### A3. Khiếu nại và chat "Hỗ trợ đơn hàng" — [booking-complaint.md](booking-complaint.md)

| Màn / thao tác | API | Ghi chú |
|---|---|---|
| Chi tiết đơn: nút Khiếu nại / Hỗ trợ | `GET /bookings/{id}` | `canComplain` → nút **Khiếu nại**. `complaint` khác `null` → trạng thái + nút **Hỗ trợ đơn hàng** |
| Tải ảnh minh chứng (tùy chọn) | `POST /bookings/{id}/complaint-evidence-upload-url` | Như cũ |
| Gửi khiếu nại | `POST /bookings/{id}/complaint` | Đơn **đang diễn ra** (`CONFIRMED`) cũng gửi được. Response có `conversationId` → mở chat ngay |
| Đầu khung chat (đơn + KTV + khiếu nại) | `GET /bookings/{id}/complaint` | Trả `booking`, `technician`, `reasonLabel`, `detail`, `statusLabel`, `conversationId` |
| Nhắn tin với CSKH | `GET` / `POST /conversations/{conversationId}/messages` | Dùng lại API chat có sẵn |
| Gửi thêm ảnh | `POST /conversations/{conversationId}/image-upload-url` | Như chat thường |
| Đánh dấu đã đọc | `PATCH /conversations/{conversationId}/read` | |
| Danh sách "Hỗ trợ đơn hàng" | `GET /conversations?type=COMPLAINT` | Mỗi phần tử có `complaint.bookingCode`, `complaint.statusLabel`; `participant` = MATXXA CSKH |

Tin hệ thống trong chat khiếu nại (`type: "SYSTEM"`, chữ có sẵn ở `text`, chọn kiểu theo `systemEvent`):
`COMPLAINT_CREATED`, `SUPPORT_AGENT_JOINED`, `COMPLAINT_STATUS_CHANGED` (kèm `complaintStatus` → cập nhật nhãn ở đầu chat).

Thông báo mới: `COMPLAINT_STATUS_CHANGED` ("Khiếu nại đơn #ECEE5154: Đã giải quyết") → mở `matxa://chat/{conversationId}`.
CSKH trả lời đến dưới dạng `CHAT_MESSAGE_RECEIVED` có `conversationType: "COMPLAINT"`.

## B. App KTV — [open-booking-waiting.md](open-booking-waiting.md) mục 2.2–2.4

| Màn / thao tác | API | Ghi chú |
|---|---|---|
| Tab "Việc của tôi" | `GET /technician/jobs?city=…&serviceIds=a,b,c&status=COMPLETED` | Lọc thành phố (1), **nhiều dịch vụ** (`serviceIds`), chip "Đã hoàn thành" |
| Danh sách thành phố cho bộ lọc | `GET /locations/cities` | |
| Danh sách dịch vụ cho bộ lọc | `GET /service-catalog` | |
| Chi tiết việc | `GET /technician/jobs/{id}` | |
| **Nhận đơn** (thẻ "Khách đặt bạn") / **Ứng tuyển** (thẻ "Yêu cầu mới") | `POST /technician/jobs/{id}/apply` | Không body. Xem bảng kết quả bên dưới |
| Từ chối (thẻ "Khách đặt bạn") | `POST /technician/jobs/{id}/decline` | |
| Rút ứng tuyển | `POST /technician/jobs/{id}/withdraw` | |
| Liên hệ khách (sau khi nhận) | `GET /technician/jobs/{id}/contact` | |
| Hoàn thành | `POST /technician/jobs/{id}/complete` | Khi `canComplete: true` |

**Kết quả `POST /apply`:**

| Response | Hiện |
|---|---|
| `bookingStatus: "CONFIRMED"` | Sheet **"Nhận đơn thành công"** – đã có địa chỉ đầy đủ và liên hệ khách |
| `status: "APPLIED"` | **"Đã ứng tuyển – Đang chờ khách xác nhận"**. **Không** hiện "Nhận đơn thành công" |
| `409 "Don khong con mo de ung tuyen"` | Đơn đã có KTV khác nhận → tải lại |
| `409 "So du vi khong du de nhan don"` | "Số dư ví không đủ" + nút Nạp ví |

**Hiện thẻ / chi tiết theo `displayStatus`:**

| `displayStatus` | Thẻ | Nút |
|---|---|---|
| `REQUESTED` | 🔥 Khách đặt bạn + đếm ngược | **Từ chối** + **Nhận đơn** |
| `NEW` | ☀️ Yêu cầu mới + đếm ngược | **Ứng tuyển** |
| `APPLIED` | Đang chờ khách xác nhận | "Đã ứng tuyển" (xám) — **chỉ** ở trạng thái này |
| `NOT_SELECTED` | Không được chọn / Khách đã chọn KTV khác | Xem đơn khác |
| `UNAVAILABLE` | Bạn không thể nhận đơn này (lý do ở `unavailableReason`) | Xem đơn khác |
| `DECLINED` / `WITHDRAWN` | Đã từ chối / Đã rút | — |
| `CANCELLED` / `EXPIRED` | Đã hủy / Hết hạn | Xem đơn khác |
| `ACCEPTED` | Đơn đã nhận | **Liên hệ khách**, **Đã hoàn thành** |
| `COMPLETED` | Đã hoàn thành | — |

**Các trường hiển thị khác:**

| Figma | Trường |
|---|---|
| Đếm ngược "12:05" | `applicationDeadlineAt` |
| "Khách nữ, Việt Nam" | `customer.gender`, `customer.nationality` |
| Địa chỉ | `addressText` (đầy đủ); nếu `null` → `district, city`. Rút gọn: `addressPreview` |
| "Khoảng cách: 5km" | `distanceKm` (ẩn nếu `null`) |
| "Bạn sẽ nhận được" / "Thực nhận" | `pricing.technicianEarning` (đã trừ hoa hồng) |
| "Gửi về Psyocore" | `pricing.platformFee` |
| "Tổng thu từ khách" | `totalAmount` |

**Thông báo KTV cần xử lý:** `OPEN_BOOKING_REQUESTED` / `OPEN_BOOKING_AVAILABLE` (đơn mới),
`TECHNICIAN_SELECTED` (được chọn), `TECHNICIAN_NOT_SELECTED` (đơn đã có KTV khác nhận),
`BOOKING_CANCELLED`, `BOOKING_EXPIRED` → tải lại `GET /technician/jobs`.

**Quy tắc cần biết:** mỗi KTV chỉ làm **1 đơn một lúc**. Khi KTV được nhận 1 đơn, backend tự rút các ứng tuyển
khác và từ chối thay các đơn khách đặt riêng KTV đó.

## C. Kiểm tra nhanh trên Swagger

1. Khách `POST /bookings` chọn KTV A → KTV B `GET /technician/jobs/{id}` thấy `displayStatus: "NEW"`.
2. KTV A `POST /technician/jobs/{id}/apply` → `bookingStatus: "CONFIRMED"`.
3. KTV B `GET /technician/jobs/{id}` → `displayStatus: "NOT_SELECTED"`, `canApply: false`; `POST .../apply` → `409`.
4. Khách `POST /bookings/{id}/complaint` → có `conversationId`; `GET /bookings/{id}/complaint` → có `booking`, `technician`.
5. Khách `GET /conversations/{conversationId}/messages` → có tin `COMPLAINT_CREATED`.
